# 版本与兼容性

LogoDock 同时提供静态网站、原始素材和 JSON 索引，目前不发布 npm 图标包。仓库版本、素材内容和元数据结构的版本分别维护。

## 数据维护来源

- `logos/<id>/metadata.json` 与登记的原始文件是维护来源。
- `index.json` 和 `docs/catalog.md` 由 `npm run build:index` 生成，不手工编辑。
- `static/`、`_site/` 和 `.svelte-kit/` 是本地构建产物，不提交。
- `src/` 内部函数、组件拆分和测试辅助模块不是公共 API；调整它们时仍须保留网站行为与既有链接。

## 品牌 ID 与文件路径

已经公开的品牌 ID 和 `logos/<id>/<asset-file>` 路径应保持稳定，不能只因修改中文名称、网站分类或内部目录整理而改名。

- 新增品牌、版本和格式使用新的稳定路径，保留已有文件的来源与使用条件。
- 更新文件内容时同步摘要、字节数和受影响的来源记录，并在变更记录中说明。同一路径的当前内容可能变化，固定完整 commit SHA 的链接用于引用旧快照。
- 必须重命名或删除文件时，列出旧路径、原因及替代路径；没有替代资源时明确说明。资源纠错或权利请求需要移除文件时，记录实际处理结果，不承诺永久保留有问题的资源。
- 不通过静默改写索引字段、品牌 ID 或路径制造不兼容变化。

## 元数据结构

当前 `schemaVersion` 为 `3`，它表示元数据结构，不等同于 `package.json` 的项目版本。

- 增加必填字段、删除字段、收紧原本允许的值或改变字段含义，需要评估为不兼容变化，提供迁移方式并更新相应结构版本。
- 新增可选信息需让旧记录仍可校验，并检查索引、录入工具、网页和测试是否一致。
- 分类是开放的非空标签。现有标签有常用中文显示名，新标签按原值显示；新增分类无需改写品牌 ID、移动文件或升级结构版本。
- Schema、运行时校验器、录入工具与消费者必须在同一变更中保持一致。结构升级时明确旧记录的迁移要求，不依据文件名推断数据版本。

## 发布记录

面向使用者的变化记入根目录 `CHANGELOG.md` 的“未发布”部分，包括重要交互、素材增删、路径变化及数据契约变化。

正式建立版本标签或 GitHub Release 时，再将已发布内容整理到对应版本与日期，并同步 `package.json` 和 lockfile。`0.x` 阶段同样需要说明破坏兼容性的变化，不能把当前包版本号当作已经发布的证明。

部署网站与发布仓库版本是不同操作。主分支的 Pages 发布必须先通过代码、数据、生成文件一致性、构建、Node 测试和浏览器回归；本地检查成功不代表远端发布已完成。
